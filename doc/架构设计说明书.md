# 实体链接与知识对齐智能体架构设计说明书

## 1. 项目概述

本项目为课题 10"实体链接与知识对齐智能体"的工程实现，对外提供归一化的 HTTP API 服务。核心功能是将文本中已识别的实体指称（mention）链接到知识库中的标准实体，输出标准实体 ID、标准名称、链接依据和可追溯信息。

项目定位为企业级可用服务，要求：

- 可独立部署，可被流水线注册式集成
- 输入输出格式归一化、稳定、可版本化
- 每次处理结果可追溯、可回放
- 可私有化部署，不依赖外部网络
- 有完整评测能力，指标可量化、可复现

## 2. 技术选型

| 组件 | 选型 | 原因 |
| --- | --- | --- |
| 语言 | Python 3.10+ | 生态成熟，NLP 工具链完整 |
| Web 框架 | FastAPI | 自动生成接口文档，性能好，支持异步 |
| 数据校验 | Pydantic v2 | 与 FastAPI 深度集成，字段校验严格 |
| 配置管理 | pydantic-settings + PyYAML | 环境变量与业务配置分离 |
| 知识库存储 | JSON 文件（第一版） | 零依赖，便于私有化部署，后续可替换为数据库 |
| 容器化 | Docker + docker-compose | 一键部署，环境一致性 |
| 测试框架 | pytest + httpx | 支持异步接口测试 |
| 项目管理 | pyproject.toml | Python 现代项目标准 |

## 4. 分层架构

本项目采用四层架构，每层只向下调用，不向上调用。

```
HTTP 请求
    ↓
中间件层（logging、error_handler）
    ↓
路由层（api/v1/）      接收请求，校验入参，返回响应
    ↓
服务层（services/）    编排核心能力调用顺序，组装响应结构
    ↓
核心能力层（core/）    每个文件只负责一个能力，互相独立
    ↓
存储层（storage/）     读写知识库文件，维护名称索引
```

| 层 | 职责 | 不做什么 |
| --- | --- | --- |
| 路由层 | 接收 HTTP 请求，字段校验，调用 Service，返回响应 | 不写业务逻辑 |
| 服务层 | 编排核心能力，组装最终响应 | 不直接操作存储，不写链接算法 |
| 核心能力层 | 候选召回、打分、NIL、共指各自独立 | 不知道 HTTP，不操作文件 |
| 存储层 | 读写知识库 JSON，维护名称索引 | 不写业务逻辑 |

分层的好处：

- 换掉存储层（如 JSON 换数据库），不影响核心能力层
- 升级某个核心能力（如候选召回换向量检索），不影响路由层和服务层
- 每层可以独立测试

## 5. 配置管理

配置分两类，分开管理：

| 文件 | 内容 | 是否提交代码库 |
| --- | --- | --- |
| `config.yaml` | 业务逻辑配置：链接参数默认值、共指触发词、实体类型等 | 是 |
| `.env` | 环境配置：端口、路径、日志级别等 | 否 |
| `.env.example` | 环境变量模板，说明需要配置哪些变量 | 是 |

`app/config.py` 统一读取两个配置文件，对外暴露配置对象，其他模块从这里获取配置，不直接读文件。

## 6. 数据模型

核心数据模型定义在 `app/models/` 下，所有接口输入输出均基于这些模型：

| 模型 | 位置 | 用途 |
| --- | --- | --- |
| `LinkRequest` | `models/request.py` | 实体链接接口请求体 |
| `LinkResponse` | `models/response.py` | 实体链接接口响应体 |
| `LinkResult` | `models/response.py` | 单个 mention 的链接结果 |
| `Entity` | `models/entity.py` | 知识库标准实体 |
| `KnowledgeBase` | `models/entity.py` | 知识库元信息 |
| `LinkStatus` | `models/enums.py` | 链接状态枚举 |
| `EvidenceType` | `models/enums.py` | 链接依据类型枚举 |
| `EntityType` | `models/enums.py` | 实体类型枚举 |

枚举值固定，不随业务变化而随意增删，变更须同步更新接口设计文档。

## 7. 部署说明

**本地运行：**

```bash
pip install -e ".[dev]"
cp .env.example .env
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

**Docker 部署：**

```bash
cp .env.example .env
docker-compose up
```

服务启动后：
- 接口文档：`http://localhost:8000/docs`
- 健康检查：`http://localhost:8000/health`

知识库数据和日志通过 volume 挂载到宿主机，容器重启不丢失。
