# 实体链接与知识对齐智能体接口设计文档

## 1. 接口总览

```text
知识库管理
  POST  /api/v1/knowledge-bases
  POST  /api/v1/knowledge-bases/import-file
  POST  /api/v1/knowledge-bases/import-upload
  GET   /api/v1/knowledge-bases
  GET   /api/v1/knowledge-bases/{kb_id}

核心接口
  POST  /api/v1/entity-link

服务接口
  GET   /health
```
## 2. 服务接口

### GET /health

检查服务是否正常运行。

响应示例：

```json
{
  "status": "ok",
  "service": "entity-link-agent",
  "version": "v1"
}
```

## 3. 知识库管理接口

### POST /api/v1/knowledge-bases

一步导入知识库元信息和实体列表。如果 `kb_id` 已存在，则覆盖原知识库内容。

请求体示例：

```json
{
  "kb_id": "kb-001",
  "kb_version": "v1",
  "description": "能源行业企业实体知识库",
  "entities": [
    {
      "entity_id": "E001",
      "canonical_name": "国网江苏省电力有限公司",
      "entity_type": "ORG",
      "aliases": ["国网江苏电力", "江苏电力"],
      "former_names": [],
      "parent_ids": [],
      "description": "国家电网有限公司在江苏地区的省级电力公司。",
      "keywords": ["江苏", "南京", "电力"]
    }
  ]
}
```

响应示例：

```json
{
  "kb_id": "kb-001",
  "kb_version": "v1",
  "entity_count": 1,
  "status": "created"
}
```

实体字段说明：

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `entity_id` | 是 | 实体唯一 ID |
| `canonical_name` | 是 | 标准实体名称 |
| `entity_type` | 是 | 实体类型，如 `ORG`、`PERSON`、`LOC`、`OTHER` |
| `aliases` | 否 | 别名、简称列表，没有传空数组 |
| `former_names` | 否 | 曾用名列表，没有传空数组 |
| `description` | 否 | 实体描述，用于上下文消歧 |
| `parent_ids` | 否 | 上位实体 ID 列表 |
| `keywords` | 否 | 消歧关键词 |

### POST /api/v1/knowledge-bases/import-file

从服务器本地文件读取并转换为项目要求的知识库格式。支持 `KBPackage JSON`、实体数组 JSON/JSONL、CCKS2019 `kb_data` JSON/JSONL、PDF 和文本文件。结构化文件可直接转换；PDF/文本属于非结构化内容，默认无法稳定转化，需要设置 `use_llm: true` 并配置 `DEEPSEEK_API_KEY` 或 `LLM_API_KEY`。

请求体示例：

```json
{
  "file_path": "E:\\平时\\2026实训\\阶段2\\ccks2019_el\\kb_data",
  "kb_id": "ccks2019-v1",
  "kb_version": "v1",
  "description": "CCKS2019 实体链接知识库",
  "source_type": "ccks_kb_data",
  "import_to_store": true,
  "include_entities": false,
  "preview_limit": 5,
  "use_llm": false
}
```

字段说明：

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `file_path` | 是 | 服务端本地文件路径 |
| `kb_id` | 否 | 导入后的知识库 ID，不填则使用文件名生成 |
| `kb_version` | 否 | 知识库版本，默认 `v1` |
| `description` | 否 | 知识库描述 |
| `source_type` | 否 | `auto`、`kb_package`、`entities`、`ccks_kb_data`、`pdf`、`text` |
| `import_to_store` | 否 | 是否直接写入知识库目录 |
| `include_entities` | 否 | 是否在响应中返回完整实体列表，实体很多时建议关闭 |
| `preview_limit` | 否 | 响应中预览实体数量 |
| `use_llm` | 否 | 是否调用大模型从 PDF/文本中抽取实体 |

响应示例：

```json
{
  "status": "created",
  "imported": true,
  "source_type": "ccks_kb_data",
  "file_path": "E:\\平时\\2026实训\\阶段2\\ccks2019_el\\kb_data",
  "kb_id": "ccks2019-v1",
  "kb_version": "v1",
  "description": "CCKS2019 实体链接知识库",
  "entity_count": 399252,
  "warnings": ["detected_source_type=ccks_kb_data"],
  "entities_preview": []
}
```

无法转化时返回 `400`，错误格式示例：

```json
{
  "detail": {
    "code": "UNSTRUCTURED_TEXT_REQUIRES_LLM",
    "message": "PDF/text is unstructured. Set use_llm=true and configure DEEPSEEK_API_KEY or LLM_API_KEY to extract entities.",
    "warnings": ["pdf_text_chars=12000"]
  }
}
```

### POST /api/v1/knowledge-bases/import-upload

从浏览器或客户端上传文件并转换为知识库。该接口用于网页中的“选择文件”按钮，会触发系统文件选择窗口，不需要用户手动复制本机路径。

请求类型为 `multipart/form-data`。

字段说明：

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `file` | 是 | 上传的 `.json`、`.jsonl`、`.pdf`、`.txt` 或 `.md` 文件 |
| `kb_id` | 否 | 导入后的知识库 ID，不填则使用上传临时文件名生成 |
| `kb_version` | 否 | 知识库版本，默认 `v1` |
| `description` | 否 | 知识库描述 |
| `source_type` | 否 | `auto`、`kb_package`、`entities`、`ccks_kb_data`、`pdf`、`text` |
| `import_to_store` | 否 | 是否直接写入知识库目录 |
| `include_entities` | 否 | 是否在响应中返回完整实体列表 |
| `preview_limit` | 否 | 响应中预览实体数量 |
| `use_llm` | 否 | 是否调用大模型从 PDF/文本中抽取实体 |

PowerShell 调用示例：

```powershell
$form = @{
  file = Get-Item "E:\平时\2026实训\阶段2\ccks2019_el\kb_data"
  kb_id = "ccks2019-v1"
  kb_version = "v1"
  source_type = "ccks_kb_data"
  import_to_store = "true"
  use_llm = "false"
}

Invoke-RestMethod -Method Post -Uri "http://localhost:8000/api/v1/knowledge-bases/import-upload" `
  -Form $form
```

### GET /api/v1/knowledge-bases

列出所有已注册的知识库。

响应示例：

```json
{
  "knowledge_bases": [
    {
      "kb_id": "kb-001",
      "kb_version": "v1",
      "entity_count": 100,
      "description": "能源行业企业实体知识库"
    }
  ]
}
```

### GET /api/v1/knowledge-bases/{kb_id}

查看指定知识库的详细信息。

响应示例：

```json
{
  "kb_id": "kb-001",
  "kb_version": "v1",
  "entity_count": 100,
  "description": "能源行业企业实体知识库"
}
```

## 4. 核心接口

### POST /api/v1/entity-link

实体链接主接口。输入文本、mention 列表和知识库引用，输出每个 mention 对应的标准实体、链接结果和依据。

**请求体示例：**

```json
{
  "schema_version": "v1",
  "request_id": "req-001",
  "text": {
    "content": "国网江苏电力完成南京重点片区供电保障。该公司表示将继续提升供电可靠性。",
    "language": "zh"
  },
  "mentions": [
    {
      "mention_id": "m1",
      "surface_form": "国网江苏电力",
      "start_offset": 0,
      "end_offset": 6
    },
    {
      "mention_id": "m2",
      "surface_form": "该公司",
      "start_offset": 19,
      "end_offset": 22
    }
  ],
  "knowledge_base": {
    "kb_id": "kb-001",
    "kb_version": "v1"
  },
  "options": {
    "top_k": 5,
    "nil_threshold": 0.6,
    "enable_nil": true,
    "enable_coreference": true,
    "return_candidates": true,
    "return_evidence": true,
    "linker_version": "v1"
  }
}
```

请求字段说明：

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `schema_version` | 是 | 输入格式版本，当前固定为 `v1` |
| `request_id` | 是 | 调用方生成的请求唯一 ID，用于追踪和回放 |
| `text.content` | 是 | 待处理原文 |
| `text.language` | 否 | 文本语言，默认 `zh` |
| `mentions[].mention_id` | 是 | mention 唯一 ID |
| `mentions[].surface_form` | 是 | mention 在文本中的原始写法 |
| `mentions[].start_offset` | 是 | mention 在文本中的起始字符位置 |
| `mentions[].end_offset` | 是 | mention 在文本中的结束字符位置 |
| `knowledge_base.kb_id` | 是 | 使用哪个知识库 |
| `knowledge_base.kb_version` | 是 | 使用哪个知识库版本 |
| `options` | 否 | 链接参数，不传时使用默认值 |

options 字段说明：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `top_k` | 5 | 每个 mention 最多召回的候选实体数量 |
| `nil_threshold` | 0.6 | 候选最高分低于此值时判定为 NIL |
| `enable_nil` | true | 是否启用 NIL 检测 |
| `enable_coreference` | true | 是否启用共指消解 |
| `return_candidates` | true | 是否在输出中返回候选实体列表 |
| `return_evidence` | true | 是否在输出中返回链接依据 |
| `linker_version` | 最新版本 | 指定链接算法版本，主要用于评测时锁定版本 |

**响应体示例：**

```json
{
  "schema_version": "v1",
  "request_id": "req-001",
  "status": "success",
  "results": [
    {
      "mention_id": "m1",
      "surface_form": "国网江苏电力",
      "link_status": "linked",
      "entity": {
        "entity_id": "E001",
        "canonical_name": "国网江苏省电力有限公司",
        "entity_type": "ORG"
      },
      "confidence": 0.92,
      "candidates": [
        { "entity_id": "E001", "canonical_name": "国网江苏省电力有限公司", "score": 0.92 },
        { "entity_id": "E000", "canonical_name": "国家电网有限公司", "score": 0.71 }
      ],
      "evidence": [
        { "evidence_type": "alias_match", "detail": "surface_form 命中别名：国网江苏电力" },
        { "evidence_type": "context_match", "detail": "上下文包含地域词：江苏、南京" }
      ]
    },
    {
      "mention_id": "m2",
      "surface_form": "该公司",
      "link_status": "linked",
      "entity": {
        "entity_id": "E001",
        "canonical_name": "国网江苏省电力有限公司",
        "entity_type": "ORG"
      },
      "confidence": 0.85,
      "coreference": { "resolved_from": "m1", "chain_id": "c1" },
      "candidates": [],
      "evidence": [
        { "evidence_type": "coreference", "detail": "该公司回指前文 mention m1" }
      ]
    }
  ],
  "coreference_chains": [
    { "chain_id": "c1", "mention_ids": ["m1", "m2"], "entity_id": "E001" }
  ],
  "summary": {
    "total_mentions": 2,
    "linked_count": 2,
    "nil_count": 0
  },
  "trace": {
    "linker_version": "v1",
    "kb_id": "kb-001",
    "kb_version": "v1",
    "options_used": {
      "top_k": 5,
      "nil_threshold": 0.6,
      "enable_nil": true,
      "enable_coreference": true
    }
  }
}
```

响应字段说明：

| 字段 | 含义 |
| --- | --- |
| `results[].mention_id` | 对应请求中的 mention_id |
| `results[].link_status` | 链接状态，见枚举值说明 |
| `results[].entity` | 链接到的标准实体，NIL 时为 null |
| `results[].confidence` | 链接置信度，0 到 1 |
| `results[].candidates` | 候选实体列表，`return_candidates: false` 时为空数组 |
| `results[].evidence` | 链接依据列表，`return_evidence: false` 时为空数组 |
| `results[].coreference` | 共指信息，非共指 mention 时不含此字段 |
| `coreference_chains` | 全文共指链，`enable_coreference: false` 时为空数组 |
| `summary` | 本次链接统计 |
| `trace` | 本次链接运行环境，用于追溯和回放 |

## 5. 固定枚举值

### link_status

| 值 | 含义 |
| --- | --- |
| `linked` | 已链接到知识库实体 |
| `nil` | 知识库中无对应实体 |
| `ambiguous` | 候选分数太接近，无法确定 |
| `error` | 该 mention 处理失败 |

### evidence_type

| 值 | 含义 |
| --- | --- |
| `canonical_match` | 标准名命中 |
| `alias_match` | 别名命中 |
| `former_name_match` | 曾用名命中 |
| `context_match` | 上下文关键词命中 |
| `type_match` | 实体类型一致 |
| `similarity_match` | 相似性召回，当前主要体现为语义向量召回 |
| `coreference` | 共指回链 |
| `model_inference` | 模型推断（预留） |

## 6. 错误响应

所有接口错误统一格式：

```json
{
  "schema_version": "v1",
  "request_id": "req-001",
  "status": "error",
  "error": {
    "code": "MISSING_FIELD",
    "message": "mentions 字段不能为空"
  }
}
```

### 错误码

| 错误码 | 含义 |
| --- | --- |
| `MISSING_FIELD` | 必填字段缺失 |
| `INVALID_FORMAT` | 字段格式错误 |
| `KB_NOT_FOUND` | kb_id 不存在 |
| `KB_VERSION_MISMATCH` | kb_version 不匹配 |
| `EMPTY_MENTIONS` | mention 列表为空 |
| `INTERNAL_ERROR` | 服务内部错误 |
