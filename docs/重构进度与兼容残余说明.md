# 重构进度与兼容残余说明

## 一、文档目的

本文档用于记录当前实体链接智能体在“候选召回层重构”和“路由层接入”这两个方向上的实际进度，同时明确哪些部分已经完成结构性替换，哪些部分仍然保留旧结构，或者为了兼容旧代码而增加了过渡适配。

本文档不描述最终目标架构，而是描述当前代码库在本轮重构之后的真实状态，便于后续继续推进扩展节点、消歧节点和 review 节点重构。

## 二、当前已经完成的重构

### 1. 候选召回层输出已从旧候选对象切换为新引用结构

当前召回层不再把 `CandidateResult` 直接作为主输出向后传递，而是先输出更轻量的召回引用结构。

已完成的结构包括：

- `RecallCandidateRef`
- `MentionRecallResult`
- `recall_by_id`

对应代码位置如下：

- `app/core/candidate.py`
- `app/services/link_service.py`

新结构的核心特征如下：

- 每个候选只保留 `entity_id`
- 显式保留 `recall_source`
- 显式保留 `match_slot`
- mention 级别保留 `recall_status`

这样做的结果是，召回层当前已经能够独立表达“召回到了哪些实体引用”以及“这些引用是如何进入候选池的”，而不必直接携带后续消歧所需的复杂字段。

### 2. 路由层已经正式接入新召回输出

`route_mentions` 节点已经加入 LangGraph workflow，并且直接消费 `recall_by_id`，不再依赖旧的 `candidates_by_id`。

当前路由结果分为四类：

- `direct_link`
- `need_disambiguation`
- `nil_pending`
- `coreference_pending`

对应代码位置如下：

- `app/services/link_service.py`

这说明“召回层输出新结构”和“路由层消费新结构”这一段已经打通，不再只是设计层面的计划。

### 3. 唯一精确命中、空候选和共指待处理已经可以在路由层提前分流

当前路由层规则已经具备以下能力：

- 唯一精确命中进入 `direct_link`
- 候选为空进入 `nil_pending`
- 共指触发词跳过召回后进入 `coreference_pending`
- 其余情况进入 `need_disambiguation`

这一步的意义在于，后续节点不再需要对所有 mention 一视同仁地处理，而是可以逐步过渡到“按路由结果决定后续动作”的结构。

### 4. 已为本轮重构补充测试护栏

当前已补充的测试重点包括：

- 召回输出是否已经变为引用结构
- 路由层是否能够正确区分 `direct_link`、`nil_pending`、`coreference_pending`

对应测试文件如下：

- `tests/test_candidate_retrieval.py`
- `tests/test_workflow_scoring.py`

## 三、当前仍保留的旧结构与兼容适配

### 1. `CandidateResult` 仍然存在

虽然召回层主输出已经改造，但 `CandidateResult` 目前并没有删除，原因是后半段多个旧节点仍然依赖它。

当前仍直接依赖 `CandidateResult` 的模块主要包括：

- `app/core/scorer.py`
- `app/core/evidence.py`
- `app/core/nil_detector.py`
- `app/services/llm_reranker.py`
- `app/services/link_service.py` 中的后半段处理

因此，当前代码库处于“召回层新结构已接入，但后半段旧结构仍在工作”的双结构并存状态。

### 2. `materialize_recall` 是当前最关键的过渡适配函数

为了让新召回结构能够暂时接上旧的重排、NIL 判断和证据生成逻辑，当前引入了 `materialize_recall`。

该函数的作用不是最终方案，而是：

- 根据 `MentionRecallResult`
- 重新恢复出旧的 `CandidateResult` 列表
- 仅供旧的 `rerank`、`resolve` 等节点继续运行

这意味着当前后半段并没有真正完成重构，只是通过适配层把旧节点暂时保住。

### 3. `LinkState` 目前同时保留了新旧两类中间数据

当前 `LinkState` 中同时存在：

- `recall_by_id`
- `mention_routes`
- `routing_buckets`
- `candidates_by_id`

其中前面三项属于新结构，最后一项属于旧结构残留。

这说明当前状态机还不是纯净的新架构，而是“前半段已切换，后半段仍兼容”的过渡版本。

### 4. `rerank` 只对 `need_disambiguation` 的 mention 生效，但内部仍在处理旧对象

当前 `rerank` 已经不再处理全部 mention，而是先参考 `routing_buckets` 只处理 `need_disambiguation` 的 mention。

这是本轮重构中已经前进的一步。

但它内部仍然是：

- 先调用 `materialize_recall`
- 再把结果转回 `CandidateResult`
- 再调用旧的 `rescore`

所以从职责边界上看，`rerank` 的入口已开始新化，但核心处理体仍然属于旧逻辑。

### 5. `resolve` 节点也存在新旧混合

当前 `resolve` 节点已经能根据 `mention_routes` 分别处理：

- `direct_link`
- `nil_pending`
- `coreference_pending`
- `need_disambiguation`

这是新路由层带来的直接收益。

但其中：

- `direct_link` 仍需把候选重新 materialize 再走一次 `rescore`
- `need_disambiguation` 仍依赖 `candidates_by_id`
- 最终证据构造仍依赖旧的 `CandidateResult`

因此 `resolve` 节点虽然已经接入新路由结果，但还没有彻底转成“纯新结构消费节点”。

## 四、当前尚未完成的真正重构部分

### 1. 还没有正式的消歧扩展节点

当前最大缺口是：

- `route_mentions` 之后
- `rerank` 之前
- 还缺少一个专门的扩展节点

该节点的职责应该是把 `need_disambiguation` 的 mention 从“召回引用结构”扩展成“可供消歧使用的特征结构”。

也就是说，当前还没有真正的：

- `build_disambiguation_pack`

### 2. 消歧阶段需要的信息还没有独立成稳定结构

下一阶段消歧真正需要的输入，当前还没有被单独整理成统一数据结构。预计至少需要包括：

- mention 本身的信息
- mention_type
- 上下文窗口
- 候选实体标准名
- 候选实体别名与曾用名
- 候选实体类型
- 候选实体描述
- 候选实体关键词
- 召回来源与命中槽位

这些信息目前并未在 `route_mentions` 后形成正式的中间对象，而是依然分散在旧逻辑里。

### 3. `llm_rerank` 尚未迁移到新消歧输入之上

当前 `llm_rerank` 仍然消费的是 `CandidateResult` 风格的候选列表，因此它也属于后半段尚未完成重构的模块。

换句话说，LLM 复核当前仍然是建立在旧的“已打分候选对象”之上的，而不是建立在未来新的“消歧扩展包”之上的。

### 4. 证据生成与 NIL 决策尚未迁移

以下模块也仍属于旧体系：

- `evidence.py`
- `nil_detector.py`
- `scorer.py`

这几个模块后续都应该逐步从“直接接受 `CandidateResult`”转向“接受新的消歧候选对象”。

## 五、当前阶段的真实结论

目前这轮重构并不是“整个后半段已经完成”，而是：

- 候选召回层输出已重构
- 路由层已正式接入新召回输出
- 后半段通过兼容适配继续沿用旧对象

因此，当前最准确的阶段判断应该是：

1. 前半段新结构已经成立
2. 后半段新结构尚未完成
3. 当前版本可以稳定运行，但仍处于过渡态

## 六、下一步建议

后续应优先推进以下工作：

### 1. 新增扩展节点

建议在 `route_mentions` 之后新增专门扩展节点，用于生成消歧输入结构。

### 2. 将 `rerank` 改为消费扩展节点产物

完成扩展节点后，应让 `rerank` 不再依赖 `materialize_recall`。

### 3. 逐步移除 `candidates_by_id`

当 `rerank`、`resolve`、`llm_rerank` 均完成迁移后，`LinkState` 中的 `candidates_by_id` 才可以真正删除。

### 4. 最后再迁移 `evidence`、`nil_detector` 和 `review_route`

这些模块应放在后半段重构后期统一迁移，避免在中间阶段频繁改动证据结构和响应结构。
